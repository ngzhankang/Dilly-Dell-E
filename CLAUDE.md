# CLAUDE.md

This file is loaded at the start of every Claude Code session to provide persistent project context.

## Project Layout

```
hackathon-template/
├── .claude/          # Claude Code config (settings.json)
├── .github/          # PR template, issue templates
├── docs/
│   ├── ARCHITECTURE.md
│   └── snippets/     # Backend stubs copied by scripts/init.sh
├── scripts/
│   └── init.sh       # One-time scaffold script (run via make init)
├── frontend/         # Generated by init.sh — not committed
├── backend/          # Generated by init.sh — not committed
├── CLAUDE.md         # This file
├── CONTRIBUTING.md
├── AI_USAGE.md
├── Makefile
├── docker-compose.yml
└── .env.example
```

## Commands

```bash
make init        # Scaffold frontend and backend (run once after clone)
make dev         # Start both servers in watch mode
make build       # Production build
make lint        # Lint both
make docker-up   # Start MongoDB + Redis
```

## Coding Standards

- TypeScript strict mode everywhere
- Use Zod for all env parsing and external data validation — never access `process.env` directly outside `src/config/env.ts`
- Prefer named exports over default exports
- Route handlers must use `asyncHandler` wrapper — no bare async/await in Express routes
- Error responses must go through `errorHandler` middleware

## Git Workflow

- Branch naming: `feat/`, `fix/`, `chore/`
- Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`
- No force-push to main
- Fill in `AI_USAGE.md` before hackathon submission if AI tools were used

## Code Review Checklist

When reviewing a PR, check:
- [ ] TypeScript errors: `tsc --noEmit`
- [ ] No raw `process.env` access outside `src/config/env.ts`
- [ ] Async routes wrapped in `asyncHandler`
- [ ] No secrets or `.env` values committed
- [ ] `AI_USAGE.md` updated if AI tools were used

## What NOT to Do

- Do not edit `docs/snippets/` files during development — those are template stubs, not live app code
- Do not commit `frontend/` or `backend/` — they are gitignored intentionally
- Do not commit `.env` — use `.env.example` as the source of truth for env var names
