## Commands

```bash
make init          # Scaffold backend + choose frontend (run once after clone)
make dev           # Start backend + frontend dev server
make build         # Production build (backend)
make lint          # TypeScript type-check
make docker-up     # Start MongoDB + Redis + ML service
make docker-down   # Stop Docker services
make build-images  # Build Docker images for backend + ml-service
make push-images   # Tag and push to $REGISTRY
make k8s-apply     # Deploy to Kubernetes
make k8s-down      # Tear down Kubernetes resources
make ml-dev        # Run ML service locally with uvicorn (hot reload)
```

## Coding Standards

### TypeScript (backend)
- TypeScript strict mode everywhere
- Use Zod for all env parsing — never access `process.env` directly outside `src/config/env.ts`
- Prefer named exports over default exports
- Route handlers must use `asyncHandler` wrapper — no bare async/await in Express routes
- Error responses must go through `errorHandler` middleware
- Call ML service via `docs/snippets/ml-client.ts` pattern (reads `ML_SERVICE_URL` from env)

### Python (ml/)
- FastAPI for the inference server (`ml/app/main.py`)
- Pydantic models for all request/response shapes (`ml/app/schemas.py`)
- Model loading in `ml/app/model.py` — swap in your framework (ONNX, PyTorch, etc.)
- `MODEL_PATH` env var controls where weights are loaded from

## Git Workflow

- Branch naming: `feat/`, `fix/`, `chore/`
- Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`
- No force-push to main
- Fill in `AI_USAGE.md` before hackathon submission if AI tools were used

## Code Review Checklist

When reviewing a PR, check:
- [ ] TypeScript errors: `tsc --noEmit`
- [ ] No raw `process.env` access outside `src/config/env.ts`
- [ ] Async routes wrapped in `asyncHandler`
- [ ] No secrets or `.env` values committed
- [ ] `AI_USAGE.md` updated if AI tools were used

## What NOT to Do

- Do not edit `docs/snippets/` files during development — those are template stubs, not live app code
- Do not commit `frontend/`, `mobile/`, or `backend/` — they are gitignored intentionally
- Do not commit `.env` — use `.env.example` as the source of truth for env var names
- Do not commit model weight files (`*.pt`, `*.onnx`, `*.bin`) — gitignored, mount via volume or bake into Docker image
